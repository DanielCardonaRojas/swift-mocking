# Interactive DocC Tutorials — Design

Date: 2026-08-11
Status: Approved (user selected full series + assessments)

## Goal

Add an interactive tutorial series to the published DocC site
(https://danielcardonarojas.github.io/swift-mocking/documentation/swiftmocking/)
following https://www.swift.org/documentation/docc/building-an-interactive-tutorial.

Today the site is generated purely from source doc comments — there is no
`.docc` catalog. This work introduces the catalog plus a Tutorials tab.

## Approach

Create `Sources/SwiftMocking/SwiftMocking.docc/`. SPM auto-discovers catalogs in
target sources, so `Scripts/docs.sh` and `swift package generate-documentation`
pick it up with zero build-script changes (swift-docc-plugin 1.4.5+ already a
dependency). No Package.swift changes.

## Structure

```
Sources/SwiftMocking/SwiftMocking.docc/
├── SwiftMocking.md                    # module extension: abstract, Get Started, curated topics
├── Table Of Contents.tutorial         # @Tutorials(name: "SwiftMocking") + @Intro + 3 @Chapters
├── mocking-your-first-protocol.tutorial    # Ch1 Getting Started (~10 min)
├── matching-arguments.tutorial             # Ch2 Argument Matching (~10 min)
├── dynamic-stubbing.tutorial               # Ch3 Advanced (~10 min)
├── verifying-interactions.tutorial         # Ch3 Advanced (~10 min)
└── Resources/
    ├── 8 PNG images (TOC hero, 3 chapter cards, 4 page intros)
    └── code listing .swift files (one per @Code step, cumulative file state)
```

## Curriculum

1. **Mock Your First Protocol** — `@Mockable` protocol, the generated
   `Mock<Name>` class shape, stubbing with `when().thenReturn`, first
   `verify().called(n)`. Built on the `Store`/`PricingService` example.
2. **Matching Arguments** — `.any` vs literals/`.equal`; predicates and ranges
   (`.lessThan`, `.greaterThan`, `.in(...)`, `.hasCount(in:)`, `.any(that:)`);
   optional matchers; `captured { }` inspection.
3. **Dynamic Stubbing** — typed `thenReturn { a, b in ... }` closures; stub
   ordering (specific matchers first, later stubs for the same matcher win);
   side effects with `.do { }`; callback-based APIs (`.any` on the closure,
   invoking completions from the stub).
4. **Verifying Interactions** — `.called()` (exactly once by default),
   `.called(n)`, `verifyNever`, `verifyZeroInteractions`; `verifyInOrder`
   across mocks; debugging failed verifications (error messages, logging).

Each page ends with 1–2 `@Assessments` multiple-choice questions with hints.

## Content accuracy rules

Verified against source before writing:

- Mock class name: `Mock<ProtocolName>` (default option; `@unchecked Sendable`).
- `.called()` asserts **exactly once** (default `.equal(1)`), not "at least once".
- The README's `.then { }` alias does **not exist** in code — use
  `.thenReturn { ... }` for closures/Void and `.do { ... }` for side effects.
- Avoid zero-parameter methods and property getters in examples (known
  macro limitation: stubbing them is silently ignored).
- Matchers: `.any`, `.equal`, `.lessThan`, `.greaterThan`, `.in(range)`,
  `.hasCount(in:)`, `.notNil()`, `.nil()`, `.identical(_:)`, `.any(that:)`,
  `.anyError()`, `.error(_:)`.

## Images

Generated by `Scripts/generate-tutorial-images.swift` (Swift + CoreGraphics;
committed so images are regenerable). 1600×900 gradient cards with chapter
color coding: Ch1 blue, Ch2 purple, Ch3 orange, TOC hero mixed gradient.

## Verification

1. `swift package --allow-writing-to-directory .build/docs generate-documentation
   --target SwiftMocking --output-path .build/docs --disable-indexing
   --transform-for-static-hosting` — must complete with no warnings (DocC warns
   on malformed directives, missing resources, unresolved links).
2. Serve `.build/docs` over HTTP and browser-verify: Tutorials tab renders TOC,
   chapter navigation, tutorial pages with step progression, code diffs, and
   working quiz interactions.
3. `swift build` still clean (catalog is inert to compilation).

## Non-goals

- No changes to `Scripts/docs.sh`, `Package.swift`, or any Swift source.
- No async/throwing deep-dive page, closure-based-dependency (Spy + adapt) page,
  or test-isolation page — candidates for a later volume.
